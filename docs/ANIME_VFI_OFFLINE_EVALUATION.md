# Anime VFI offline evaluation

Date: 2026-09-03

Status: one host comparison, one bounded physical-device native probe, and one resident-process
resolution ladder completed. This is not a player integration, realtime claim, visual-quality
approval, sustained thermal result, or model redistribution approval.

## Outcome

Only RIFE ncnn Vulkan v4.6 advances as the current offline mobile probe. IFRNet-S remains a host
comparison. The decision is narrow: on the same project-generated 320x180 line-art motion pair,
RIFE produced a substantially better ground-truth proxy result, while IFRNet-S was smaller and
faster. Neither result is evidence for representative anime or normal playback.

No file under `app/` changed. `QuickSrVideoEffect`, Media3 frame ownership, QNN queueing, cadence
reuse, and Anime4K remain authoritative and unchanged. VFI is still an optional smooth-mode
experiment whose default state is absent/off.

## Decision contract

`VfiPrefilter` in `vfi-benchmark/vfi_prefilter.py` consumes decoded frames in presentation order:

1. no prior frame, stream-epoch change, or generation change: `BYPASS` and replace the anchor;
2. exact identity or bounded near-hold difference: `BYPASS`;
3. high whole-frame change meeting both cut thresholds: `BYPASS`;
4. otherwise: `INTERPOLATE / DISTINCT_DRAWING`.

This makes fixed odd/even selection and blind interpolation impossible in the offline runner. The
project-generated fixture has 12 events: one true distinct pair interpolates, while the first
frame, exact hold, near hold, hard cut, seek generation change, and stream-epoch changes all bypass.
The fixture manifest SHA-256 is
`2e829049491b35e4838a7ed7a657b999d8f9b37064f17af0ec6c457e6deb90af`.

## Resident-process resolution ladder

The follow-up fixture generates seven project-owned, visually distinct source frames and six exact
known midpoints at each resolution. The existing prefilter accepted all six adjacent pairs as
`INTERPOLATE / DISTINCT_DRAWING`. One directory-mode process initializes Vulkan and loads RIFE v4.6
once, then emits 14 upstream tasks. Midpoint task IDs are `1/3/5/7/9/11`: the first is warmup and the
remaining five form the unpolled stable distribution. A second process is used only for PSS/RSS
sampling and is excluded from latency statistics.

Before any device work, the runner now requires the expected manifest schema and level metadata,
exactly seven input plus six ground-truth files per level, matching bytes/SHA-256 and pixel
dimensions, and an exact match between manifest decisions and a fresh prefilter replay over the
actual inputs. Every input is then SHA-256 checked again on device immediately after `adb push`.
Ground truths are rechecked immediately before scoring. Model/decode/encode timing IDs must each be
exactly `0..13` with no gaps or duplicates. The ignored raw report binds all local and remote input
identities and has SHA-256
`626c9123eac3ed73899caca37fabb8a5d2829271a9e95e4be7d0d03ae2455848`.

Cold Vulkan initialization was 23.446-24.592 ms and model loading was 1346.619-1650.405 ms. The
first midpoint warmups were 78.600-171.670 ms; whole-process times were 1886.056-2456.608 ms.
These are separate clocks: upstream decode/model/encode tasks overlap in a pipeline and must not be
summed. The within-run spread and material drift from the superseded preliminary pass are retained
as limitations rather than smoothed away; this bounded pass does not control clocks or prove
sustained performance.

All levels produced 14 hashed PNG outputs and six quality comparisons. Mean PSNR ranges from
26.378 to 31.073 dB, global SSIM from 0.980406 to 0.992237, and edge-gradient MAE from 0.003138 to
0.010590. These synthetic known-midpoint proxies validate execution and scoring only; human review
remains pending. Corrected temperature-zone maxima were at most 48.0 C, threshold/limit zones were
excluded, and the battery proxy remained between 35.8 and 36.0 C. This is not a sustained thermal
result.

### Budget decision

The comparison budgets are 33.333 ms for 30 fps, 41.667 ms for 24 fps, and 83.333 ms for one
12-to-24 fps source interval. At 160x90 all five model calls fit the 30 fps kernel-only budget, but
the 32.008 ms maximum leaves only about 1.325 ms. At 320x180 all calls fit 24 fps, but the 37.806 ms
maximum leaves only about 3.860 ms. The 256x144 and 480x270 medians miss both 24 and 30 fps budgets.
At 640x360 the 75.053 ms median fits one 12-to-24 interval, but the 85.062 ms maximum does not.

Those clocks omit player scheduling, video decode, SR, composition, final display, A/V sync, and
sustained thermal behavior. Therefore no resolution has meaningful end-to-end realtime margin and
the candidate remains offline-only. The next bounded hypothesis is low-resolution VFI followed by
the existing SR or Anime4K path; it is recorded here, not implemented in this branch.

## Reproduction and publication boundary

`vfi-benchmark/README.md` provides host commands. The Android build
script verifies the upstream and submodule commits, applies the timing patch, and builds only the
native probe. The Android runner verifies one connected serial, remote file hashes, PSS/RSS,
temperature proxies, model and end-to-end wall time, outputs, and process exit.

Committed files contain only source, links, hashes, manifests, tests, sanitized measurements, and
this report. Source/model clones, release archives, weights, binaries, PNGs, outputs, device reports,
and remote evidence stay below ignored `local-artifacts/` or `/data/local/tmp`. No push is part of
this task.

## Still unproven

- representative rights-clear anime clips, difficult occlusion, pans, subtitles, line boil, and
  more than one known synthetic midpoint;
- LPIPS, warp/flicker metrics, and human visual review;
- player-resident Android runtime ownership, scheduling, A/V sync, seek/flush integration,
  sustained 10-30 minute temperature/power, or a safe frame-rate policy;
- compatibility outside the single observed device/firmware/driver;
- model-weight redistribution rights.

Therefore the mergeable core is limited to the prefilter/decision contract, reproducible fixture,
candidate/rights manifests, standalone host/device probe tooling, and evidence report. Integrating
VFI into the default or optional player path requires a separate review after the open gates above.
